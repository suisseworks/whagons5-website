## El trabajo se está haciendo. Lo que falta es control.

Muchos problemas hoteleros no ocurren porque un equipo se niegue a actuar. Ocurren porque una solicitud pasa de una persona, departamento o turno a otro sin suficiente control operativo.

Se reporta un problema de un huésped en recepción. Ingeniería recibe un mensaje. El siguiente turno sabe que ocurrió algo, pero no si se volvió a contactar al huésped. Todos participaron y, aun así, el gerente tiene que reconstruir la historia.

Esa es una falla en la entrega operativa. Estos son siete patrones que conviene buscar.

## 1. La solicitud no tiene un responsable explícito

Enviar un mensaje a un departamento no equivale a asignar responsabilidad. Si tres personas pueden responder, cada una puede suponer que otra ya se está encargando.

Para cada flujo seleccionado, define:

- El rol responsable de la siguiente acción
- Cuándo comienza la responsabilidad
- Cuándo termina la responsabilidad
- Quién asume el trabajo si el responsable no está disponible

El responsable no tiene que ejecutar cada paso. Sí necesita saber si la entrega llega al siguiente estado controlado.

## 2. El plazo solo existe en la conversación

Palabras como «urgente», «pronto» y «antes del check-in» parecen claras hasta que dos departamentos las interpretan de manera distinta.

Utiliza una hora límite o una ventana de servicio observable. Después, decide qué debe suceder antes y después de ese momento. Un plazo sin una ruta de escalamiento solo documenta que el trabajo se atrasó.

## 3. El escalamiento comienza cuando un gerente pregunta

Si el primer escalamiento ocurre cuando un gerente revisa manualmente la solicitud, el proceso depende de que ese gerente recuerde buscarla.

Define el escalamiento al diseñar el flujo:

- ¿A quién se notifica cuando se acerca el plazo?
- ¿Quién interviene cuando el plazo se vence?
- ¿El departamento original conserva la responsabilidad sobre el trabajo?
- ¿Qué información debe incluirse en el escalamiento?

El propósito no es crear más notificaciones. Es hacer que la intervención sea predecible.

## 4. «Terminado» no tiene un estándar de cierre

Una solicitud de mantenimiento puede marcarse como completada aunque el área afectada todavía no haya sido liberada. Una habitación puede estar limpia mientras queda una excepción pendiente. Un problema del huésped puede resolverse operativamente sin que ocurra el seguimiento posterior.

Define qué exige el cierre. Según el flujo, puede ser una nota, una foto, una lista de verificación, una inspección, una aprobación o una confirmación del departamento receptor.

## 5. El siguiente turno recibe un resumen, no la responsabilidad

Las notas de turno son útiles, pero un resumen puede ocultar trabajo abierto entre información general. El equipo entrante necesita saber qué asuntos siguen abiertos, quién es ahora responsable y cuándo vence la próxima acción.

Separa las notas informativas del trabajo que requiere una acción.

## 6. Los gerentes ven actividad en lugar de excepciones

Una larga lista de tareas completadas puede parecer productiva mientras oculta las pocas entregas que más importan. Los gerentes necesitan una vista del trabajo abierto, atrasado, escalado, rechazado y reabierto repetidamente.

Comienza con preguntas sobre las excepciones:

- ¿Qué está atrasado en este momento?
- ¿Qué no tiene responsable?
- ¿Qué está esperando a otro departamento?
- ¿Qué se cerró sin la evidencia requerida?
- ¿Qué tipo de entrega falla repetidamente?

## 7. El hotel intenta corregir todos los flujos al mismo tiempo

Una transformación amplia genera más configuración, capacitación y resistencia antes de que el equipo tenga evidencia de que el enfoque funciona.

Elige un flujo que cruce un límite entre equipos o turnos y que ocurra con suficiente frecuencia para observarlo. Establece su línea base actual, mejora los puntos de control y revisa qué cambió antes de expandirlo.

## Una revisión de cinco controles para cada entrega

Toma un problema reciente del hotel y responde estas preguntas:

1. ¿Quién fue responsable de la siguiente acción en cada paso?
2. ¿Cuál era el plazo?
3. ¿Qué debía activar el escalamiento?
4. ¿Qué demostró el cierre?
5. ¿Qué podía ver el gerente sin pedir una actualización?

Cualquier respuesta que dependa de la memoria o del historial de mensajes revela una posible brecha de control. Corregir incluso una de esas brechas puede reducir el seguimiento que necesita hacer el gerente, independientemente del software que utilice el hotel.
