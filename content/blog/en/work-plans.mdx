Every hotel runs on work that repeats. Check rooms before arrivals, test the pool chlorine, run the generator on Tuesdays. When that list lives on a printed sheet or in one person's head, it falls apart the day that person is off. Work Plans is the Whagons powerup for those routines. You define once what gets done, where, by whom and how often, and Whagons creates the tasks when they are due. This guide covers how to build a plan, how to decide when tasks appear, and how to check whether the routine actually happened.

## Try this first

**Three things for your first week with Work Plans**

1. Pick a routine that already exists on paper and turn it into a plan inside the space of the team that does it.
2. In the schedule, select spots instead of copying the task. Each spot gets its own task on every run.
3. At the end of the week, open the plan's Calendar and start with the late days.

## 1. How to build the plan

### Create the plan inside the team's space

**What to do.** Go to the space of the team that does the work, for example Maintenance, open the Plans tab and use New Plan.

**Why it matters.** The plan belongs to that space. The tasks it creates land in the grid the team already works in, with the same statuses, filters and views. Nobody has to learn to check another screen.

**How.** Give the plan a name that says the routine and the place. If it reads well in a phone notification, it works:

```naming
Preventive round · Tower A
Pool and wet areas
Generator and pumps
```

### One schedule per task and frequency

**What to do.** Inside the plan, use New schedule for each task that repeats. Turn on Repeat Task and fill in Every, On days and Starts on.

**Why it matters.** A schedule is a model task with its own recurrence. It keeps the name, template, priority, tags, assignees, form, SLA and spots, so every new task comes out complete. It can repeat daily, weekly, monthly or yearly.

**How.** Split by frequency. If room checks run Monday, Wednesday and Friday and minibar checks run every day, those are two schedules in the same plan.

### Select spots instead of copying the task

**What to do.** In the schedule, select every place where the task happens under Spots. In Whagons, a spot is any location, such as a room, a floor or the pool.

**Why it matters.** With two or more spots, Whagons creates one task per spot on every run. Before you save, the screen tells you how many with a note like "Will generate 4 tasks per run". One schedule for forty rooms replaces forty tasks copied by hand, and if you change the template tomorrow, you change it once.

**How.** If the round covers whole floors, make one schedule per floor. Each supervisor then gets their part as its own row in the calendar.

### Decide when tasks appear

**What to do.** In the plan settings, pick one option under Create tasks: At scheduled time, Before scheduled time or At start of scheduled day.

**Why it matters.** It changes what the team finds when the shift starts. With the first, the task appears right at the scheduled time. With the second, it appears as early as you set in Minutes before, up to a full day. With the third, it appears at 00:00 on the scheduled day, so the morning shift already has it in the grid.

**How.** For rounds someone reviews at the start of a shift, use At start of scheduled day. For work with an exact time, like a 10:00 AM generator test, use At scheduled time.

## 2. Day to day

### The team works the tasks where it always does

**What to do.** Nothing new for the team. They open their space and find the plan's tasks in the grid, with the start time, assignees and tags from the schedule.

**Why it matters.** These are regular tasks in the space. People assign, comment on and close them like any other task, and a badge shows they came from a plan.

**How.** If someone can't see the Plans tab, check two things. Their role needs access to Work plans, and they have to be on a team that serves the space.

### Create a task off schedule

**What to do.** When you need an extra run, like a check after a storm, use Create task now on the schedule.

**Why it matters.** The task is created right away, without waiting for the next date and without touching the recurrence. It works even when the plan is disabled. A schedule with Repeat Task turned off shows as Manual and only creates tasks through this button.

**How.** Use it to test a new schedule before you let it run on its own.

### Pause the plan without losing anything

**What to do.** If the hotel closes a wing for the season, turn off Enabled in the plan settings.

**Why it matters.** While the plan is disabled, Whagons stops creating tasks and shows "This plan is disabled. No tasks are being generated." To resume, use Enable plan. Deleting a plan removes the plan and its schedules, but the tasks it already created stay in the space.

**How.** Disable instead of deleting. You keep the schedules for next season.

## 3. Checking that it happened

### Read the calendar, not your memory

**What to do.** Open the plan's Calendar view once a week. At the top you can pick Day, Week, 2 weeks or Month.

**Why it matters.** Each schedule is a row and each day is a column. A green dot is a completed day. A red triangle marks a late day, which is a past day whose task isn't finished or never existed. Each row's percentage counts completed days over all scheduled days in the range, including the ones still ahead. Midweek, it won't read 100%, and that's expected.

**How.** Start the review with the red triangles. Each one is a round that didn't happen, and someone should be able to say why.

### Find the detail in Runs

**What to do.** When something doesn't add up, open the Runs view.

**Why it matters.** It's the grid of tasks each run created. Use it for specific questions, like which task went out for room 204 on Tuesday and what status it ended in.

## 4. Three details before you let it run

### Set the deadline with an SLA

**What to do.** If the team needs a deadline for each task, set it with the schedule's SLA.

**Why it matters.** The schedule editor has Duration but no due date. Without an SLA, plan tasks start with no deadline.

### Schedule monthly work by day number

**What to do.** For a monthly routine, pick a day number, like the 15th, instead of a rule like "the second Tuesday".

**Why it matters.** Today Whagons creates monthly tasks on the same day number as the start date, even if you pick a weekday. With a day number, what you see on screen is what happens.

### End a series with a date

**What to do.** If a routine has an end, like a seasonal preventive, set Ends to On date.

**Why it matters.** Today the option to end after a number of occurrences doesn't stop the series. A date does.

## 5. Before you start

Work Plans has to be active in your organization. If you don't see the Plans tab in your spaces, ask your admin or your Whagons contact to turn it on.

The Admin, Leader and Member roles have access to Work plans by default. The Viewer role doesn't. People who aren't admins also need to be on one of the space's teams.

## Your Work Plans checklist

Run through it before you let a plan run on its own.

<Video name="work-plans-checklist" fig="D" caption="The checklist at a glance." label="Animation: a card with the Work Plans checklist in four groups. The boxes tick one by one." />

**The plan**

- [ ] Lives in the space of the team that does the work
- [ ] Has one schedule per task and frequency

**The schedules**

- [ ] Have spots selected, not tasks copied
- [ ] Have assignees and a template
- [ ] Have a decided time for task creation
- [ ] Have an SLA if the team needs a deadline

**Follow-up**

- [ ] Someone opens the Calendar at the end of the week
- [ ] Every late day has an explanation

**Permissions**

- [ ] The team's roles have access to Work plans
- [ ] Everyone is on one of the space's teams

Start with one routine. When the first week's calendar comes back green, add the next one.
